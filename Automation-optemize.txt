3. STEP-BY-STEP OPTIMIZATION ROADMAP (KAISE KRNA HAI)
================================================================================

PHASE 1: FOLDER DIRECTORY CREATION
- `pages/` ke andar `base/`, `auth/`, `customer/`, `operations/`, `admin/` banayein.
- `tests/` ke andar `api/`, `auth/`, `customer/`, `operations/`, `admin/`, `e2e/`, `visual/` banayein.

PHASE 2: PAGE OBJECTS MIGRATION & REFACTORING
- `BasePage.js` ko `pages/base/` me move karein.
- Auth related pages (`LoginPage.js`, `RegisterPage.js`, `ForgotPasswordPage.js`) ko `pages/auth/` me move karein.
- Operations pages (`ManagerPage.js`, `DispatcherPage.js`, `DriversPage.js`, `CreateOrderStudioPage.js`, `OrderActionsPage.js`) ko `pages/operations/` me move karein.
- `AdminPage.js` ko `pages/admin/` me move karein.
- `DashboardPage.js`, `ProfilePage.js`, `SettingsPage.js` ko `pages/customer/` me move karein.

PHASE 3: TEST SPECS MIGRATION & REQUIRE PATHS UPDATE
- Sabhi test specs ko unke respective domain folder me move karein.
- Sabhi spec files ke imports (`require('../../pages/...')`) ke relative paths ko new structure ke according update karein.

PHASE 4: FIXTURES IMPLEMENTATION (ADVANCED OPTIMIZATION)
- Har test me manual login/logout repeat karne ke bajaye `auth.fixture.js` banayein jo `test.use({ storageState: ... })` use karke pre-authenticated browser context provide kare.
- Isse test execution speed 3x fast ho jayegi aur session collisions khatam ho jayenge.

PHASE 5: NPM SCRIPTS & TEST TAGGING
`package.json` me role aur domain based scripts add karein:
- `npm run test:auth`        -> Sirf authentication tests run honge
- `npm run test:customer`    -> Sirf customer module tests run honge
- `npm run test:ops`         -> Manager, Dispatcher, Driver tests run honge
- `npm run test:admin`       -> Admin & Rate Matrix tests run honge
- `npm run test:api`         -> Fast API contract tests run honge
- `npm run test:e2e`         -> End-to-end multi-role flow run hoga
- `npm run test:visual`      -> UI visual regression snapshots run honge
- `npm run test:smoke`       -> Critical path sanity tests run honge

PHASE 6: CI/CD INTEGRATION & ISOLATION
- GitHub Actions me PR create hone par `test:smoke` chalayein (1-2 minutes).
- Main branch merge par full regression suite chalayein.
- Workers count environment ke according automatically adjust karein.

4. KEY BENEFITS OF THIS OPTIMIZATION
================================================================================
1. High Scalability: Naye features add hone par exact domain folder me file add hogi.
2. Clean Maintainability: Ek page/test dhoondhna aur modify karna instant hoga.
3. Fast Execution: Developer ko pura suite chalane ki zarurat nahi hogi, specific folder run kar sakte hain.
4. Zero Flakiness: Fixtures aur clean path organization se race conditions eliminate honge.

5. STRICT NON-BREAKING & FUNCTIONALITY PRESERVATION RULES (ZERO CODE BREAKAGE)
================================================================================
⚠️ IMPORTANT MANDATES:
1. ZERO FUNCTIONAL CHANGES:
   - Next.js Web Application (`Project/` folder) ke kisi bhi code, API endpoint, 
     UI component, styling ya business logic me 0% change hoga.
2. ZERO TEST LOGIC CHANGES:
   - Kisi bhi test spec ka assertion, expected status, selector, test data ya 
     verification logic modify nahi hoga.
3. ZERO LOCATOR ALTERATION:
   - Sabhi Page Object Models ke method names, actions aur DOM locators wahi 
     rahenge jo abhi chal rahe hain.
4. PURE FILE & IMPORT PATH REORGANIZATION:
   - Sirf aur sirf file locations (directories) organize honge aur unke 
     relative `require(...)` import paths adjust honge.
5. 100% GREEN PASS GUARANTEE:
   - Optimization ke baad sabhi 76 tests pehle ki tarah 100% green pass hone 
     chahiye bina kisi mismatch ke.
