SECTION 2: AUTOMATION FILES KA DEEP DIVE (KAUNSI FILE KYA KARTEE HAI)
================================================================================

📁 Automation/

1. 📄 `playwright.config.js` (The Brain / Master Controller)
   -----------------------------------------------------------------------------
   - Role: Yeh poore automation framework ka control room hai.
   - Key Duties:
     a) `webServer`: Ye Playwright ko bolta hai ki test chalane se pehle dekho ki Next.js app 3000 port par chal raha hai ya nahi. Agar nahi chal raha toh automatic `npm run start` chala kar launch kar do.
     b) `baseURL`: Baseline URL set karta hai (`http://localhost:3000`).
     c) `projects`: Multiple browsers (Chromium, Firefox, WebKit, Mobile Chrome, Mobile Safari) set karta hai.
     d) `expect.toHaveScreenshot`: Visual snapshot comparison ke liye pixel tolerance set karta hai.

2. 📁 `pages/` (Page Object Model - POM Architecture)
   -----------------------------------------------------------------------------
   POM ka matlab hai: Har web page ki apni ek dedicated Class file hoti hai jo uss page ke saare HTML Locators (Buttons, Inputs, Banners) aur Actions (Click, Fill, Text Get) ko sambhalti hai.

   a) 📄 `pages/BasePage.js` (The Parent Class)
      - Iss class me wo code hai jo har page me common hota hai:
        - `navigateTo(path)`: Browser ko specific URL par le jata hai.
        - `verifyBrandHeader()`: Top header bar ka logo (`#brand-logo`) aur badge (`.accent-badge`) verify karta hai.

   b) 📄 `pages/LoginPage.js` (Login Page Object)
      - Extends `BasePage.js`.
      - Locators: `#username`, `#password`, `#login-submit-btn`, `#error-banner`, `#success-banner`, `#autofill-btn`, `.toggle-password`, `#goto-register-link`.
      - Methods:
        - `login(username, password)`: Email & password type karke submit button click karta hai.
        - `clickAutofill()`: "Auto Fill" button click karta hai.
        - `togglePasswordVisibility()`: Password show/hide click karta hai.
        - `verifyErrorBanner()`, `verifySuccessBanner()`: Alert banners verify karta hai.

   c) 📄 `pages/RegisterPage.js` (Register Page Object)
      - Extends `BasePage.js`.
      - Locators: `#register-name`, `#register-email`, `#register-password`, `#register-confirm-password`, `#register-submit-btn`, `#register-error-banner`, `#register-success-banner`, `#goto-login-link`.
      - Methods:
        - `register(name, email, password, confirmPassword)`: Registration form fill karke Submit click karta hai.

   d) 📄 `pages/DashboardPage.js` (Dashboard Page Object)
      - Extends `BasePage.js`.
      - Locators: `#welcome-heading`, `#user-role-badge`, `#logout-btn`, `.card`.
      - Methods:
        - `verifyDashboardLoaded(userName)`: Check karta hai ki URL `/dashboard` ho gaya, username display ho raha hai, aur 3 cards present hain.
        - `logout()`: "Sign Out" button click karke logout karta hai.

3. 📁 `utils/` (Helper Utilities)
   -----------------------------------------------------------------------------
   a) 📄 `utils/testData.js` (Dynamic Test Data Generator)
      - `generateUser()`: Har test run par ek completely unique Email aur Password generate karta hai (e.g. `testuser_172000_452@qa.local`). Iss se database me duplicate email ka issue kabhi nahi aata.
      - `demoCredentials`: Pre-seeded demo user (`user@example.com` / `password123`).
      - `invalidCredentials`: Fake non-existent user data.
      - `edgeCasePayloads`: SQL/Script injection strings (`<script>alert('xss')</script>`).

4. 📁 `tests/` (The Test Execution Suites)
   -----------------------------------------------------------------------------
   a) 📄 `tests/e2e-flow.spec.js`:
      - Full User Lifecycle Test (Register -> Auto-Redirect -> Login -> Dashboard -> Logout).

   b) 📄 `tests/login.spec.js`:
      - Positive Login (Demo credentials, Autofill button, Toggle password visibility).
      - Negative Login (Invalid credentials error).
      - Edge Case (XSS Script payload safety).
      - Navigation Link (Clicking Create Account link).

   c) 📄 `tests/register.spec.js`:
      - Positive Registration (New user creation).
      - Negative Registration (Password mismatch, short password <6 chars, duplicate email).
      - Navigation Link (Clicking Sign In link).

   d) 📄 `tests/ui-checks.spec.js`:
      - Functional UI Checks (Logo, badge text, computed CSS background color `rgb(46, 111, 232)`).
      - Visual Regression Snapshot Tests (`expect(page).toHaveScreenshot()`).

   e) 📄 `tests/responsive.spec.js`:
      - Responsive layout tests across Desktop (1280x720), Tablet (768x1024), and Mobile (375x667) screen viewports.

SECTION 3: STEP-BY-STEP EXECUTION JOURNEY (CODE KAISE TRACE HOTA HAI)
================================================================================

Maan lijiye aapne terminal me ye command chalaya:
`npx playwright test tests/e2e-flow.spec.js --project=chromium`

Dekhein parde ke peeche (Behind the Scenes) kya hota hai:

Step 1: [CONFIG LOAD]
        Playwright `playwright.config.js` ko load karta hai.
        Check karta hai `http://localhost:3000` chal raha hai ya nahi. Next.js server verify hota hai.
        Chromium browser worker launch hota hai.

Step 2: [TEST FILE START]
        Worker `tests/e2e-flow.spec.js` file open karta hai.
        Top par imports execute hote hain:
        - `RegisterPage` class import hui.
        - `LoginPage` class import hui.
        - `DashboardPage` class import hui.
        - `TestDataGenerator` utility import hui.

Step 3: [DYNAMIC DATA CREATION]
        Code: `const newUser = TestDataGenerator.generateUser();`
        `testData.js` ek naya object banata hai:
        `{ name: "Automation User 78", email: "testuser_9988_78@qa.local", password: "SecurePass@78" }`

Step 4: [OPEN REGISTER PAGE]
        Code: `await registerPage.navigate();`
        `RegisterPage` apne parent `BasePage.js` ke `navigateTo('/register')` ko bolta hai.
        Browser URL kholta hai: `http://localhost:3000/register`.

Step 5: [FILL REGISTER FORM]
        Code: `await registerPage.register(newUser.name, newUser.email, newUser.password, newUser.password);`
        Playwright input `#register-name` me "Automation User 78" type karta hai.
        Playwright input `#register-email` me "testuser_9988_78@qa.local" type karta hai.
        Playwright inputs `#register-password` & `#register-confirm-password` me "SecurePass@78" type karta hai.
        Playwright `#register-submit-btn` par CLICK karta hai.

Step 6: [BACKEND API + MONGODB EXECUTION]
        Next.js App Server par `POST /api/register` Call hoti hai (`app/api/register/route.js`).
        API `lib/dbConnect.js` ke zariye MongoDB database connect karti hai.
        `models/User.js` Mongoose model me new user record create hota hai.
        API Frontend ko Response bhejti hai: `{ success: true, message: "Account created..." }`.

Step 7: [FRONTEND REDIRECT & LOGIN]
        Register Page par Green Success Alert Banner "Account created successfully" show hota hai.
        Frontend `router.push('/')` chala kar 1.2s me Login Page (`/`) par redirect ho jata hai.

Step 8: [SUBMIT LOGIN FORM]
        Code: `await loginPage.login(newUser.email, newUser.password);`
        Playwright Login Screen ke `#username` me "testuser_9988_78@qa.local" aur `#password` me "SecurePass@78" type karke `#login-submit-btn` click karta hai.
        Next.js API `POST /api/login` MongoDB me credentials verify karti hai -> `200 OK` daiti hai -> Frontend `/dashboard` par bhej deta hai.

Step 9: [DASHBOARD VERIFICATION]
        Code: `await dashboardPage.verifyDashboardLoaded("Automation User 78");`
        Playwright check karta hai ki:
        1. URL contain karta hai `/dashboard`.
        2. `#welcome-heading` me text "Welcome, Automation User 78!" hai.
        3. 3 metrics cards screen par dikh rahe hain.

Step 10: [LOGOUT & TEARDOWN]
         Code: `await dashboardPage.logout();`
         Playwright `#logout-btn` par click karta hai.
         Session clear ho jata hai aur browser wapas Login Screen (`/`) par aa jata hai.
         Playwright test ko GREEN (✓ PASSED) mark kar deta hai.

SECTION 4: VISUAL REGRESSION & RESPONSIVE TESTING DEEP DIVE
================================================================================

1. VISUAL SNAPSHOT COMPARISON (`tests/ui-checks.spec.js`):
   -----------------------------------------------------------------------------
   - Code: `await expect(page).toHaveScreenshot('login-page-visual.png')`
   - Kaise kaam karta hai:
     1. Jab pehli baar `--update-snapshots` chalate hain, Playwright UI ka screenshot kheench kar `tests/ui-checks.spec.js-snapshots/` folder me Baseline Reference Image ke roop me save kar leta hai.
     2. Agli baar jab test chalta hai, Playwright current UI ka live screenshot leta hai aur baseline image ke sath Pixel-by-Pixel compare karta hai.
     3. Agar koi element 1px bhi displacement ya color change hota hai, Playwright error report me Diff Image (Red Highlight) generate kar deta hai.

2. RESPONSIVE VIEWPORT TESTING (`tests/responsive.spec.js`):
   -----------------------------------------------------------------------------
   - Code: `await page.setViewportSize({ width: 375, height: 667 });`
   - Playwright runtime par browser window size badalta hai:
     - Desktop: 1280 x 720
     - Tablet: 768 x 1024
     - Mobile: 375 x 667
   - Aur verify karta hai ki forms, inputs, aur cards mobile/tablet screens par text overlap ya clipping ke bina properly adjust (responsive) hote hain ya nahi.

================================================================================
1. All Tests Run (Headless Mode):
   npx playwright test --project=chromium

2. All Tests Run with Browser UI Visible (Headed Mode):
   npx playwright test --project=chromium --headed

   npx playwright test tests/e2e-flow.spec.js --project=chromium --headed

4. View Detailed HTML Test Execution Report:
   npx playwright show-report

5. Update Baseline Screenshots for Visual Testing:
   npx playwright test tests/ui-checks.spec.js --update-snapshots
